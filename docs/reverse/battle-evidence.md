## 依赖关系

`Z.COM` 是 DOS 启动壳，在 `0x10195` 附近通过 `int 21h / AX=4B00h` 执行 `Z.DAT`。该调用点所在函数为 `0x1015F`–`0x101A7`，名称为 `sub_1015F`。`z.DAT` 字符串位于 `0x1010C`；由于执行参数通过寄存器与内存块传递，IDA 没有为该字符串生成普通数据交叉引用，不能据此否定执行关系。

依赖证据：

| 证据 ID | 文件 | 地址 | 状态 | 结论 |
| --- | --- | --- | --- | --- |
| `ENTRY-ZCOM-EXEC` | `Z.COM` | `0x10195` | 已确认 | 启动 `Z.DAT` |

逆向范围采用依赖闭包。如果后续调用链涉及其他 EXE、COM、覆盖模块、驱动或数据内可执行代码，应为新增文件记录哈希、加载位置和关联证据。

`DATA-WAR-LOAD` 的反编译摘要显示 `WAR.STA` 记录步长为 186 字节，并将战场图层缓存初始化为 `-1`。`ANIM-FIGHT-LOAD` 的反编译摘要显示动画索引按角色、武功类型和方向计算；完整动画帧规则仍需与战斗行动函数共同确认。

`BATTLE-MAIN-LOOP` 的反编译摘要显示原版最多初始化 26 个角色槽，玩家队伍和敌方队伍分别写入阵营、坐标、角色数据索引，并在循环中调用地图绘制、输入轮询和行动处理。每个角色开始新决策前只清空自身行动代码，因此较早角色写入的代码 `8/9` 可供同一回合后续队友读取。C++ 场景副本使用 `CharInfo::actionCode` 保存这两个持久请求标记，纯 AI 门面中的 `AiRequest` 只作为适配接口。`BATTLE-AI-SELECT` 明确包含生命、受伤、内力、中毒、医疗、解毒与 `sub_3D612(10)` 随机门槛；这些门槛和随机消费顺序已提取到 `battle::ai_policy`。

`BATTLE-AI-SELECT` 的低体力控制流已按指令确认：`0x336A0` 比较体力与 10，低于 10 时在 `0x336AA` 先把局部行动设为 7。生命恢复条件命中后，`0x337D1` 调用 `sub_33C4D`，并用返回值覆盖该行动；`0x337DF` 只在返回 0 时继续解毒、补内力和支援判断。因此低体力是延后执行的休息候选，不是立即返回。`sub_33C4D` 成功时返回 5、6 或 8，失败时显式返回 0；失败会清除原先的休息候选并继续级联。

`BATTLE-AI-HP-RECOVERY` 的自身医疗条件为 `medic >= 20`、`stamina >= 50` 且 `medic > hurt - 30`。自身医疗和生命物品均不可用时，按角色槽升序查找医疗能力严格高于 20 且高于 `hurt - 30` 的同阵营存活角色；命中后在请求者的 `CharInfo::actionCode` 保存 `8`。`BATTLE-AI-DEPOISON-RECOVERY` 的自身解毒条件更严格：`depoison > 20`、`stamina > 50` 且 `depoison > poisoned - 30`。随后使用相同槽序查找队友，并保存行动代码 `9`。`BATTLE-AI-MEDIC-TARGET` 与 `BATTLE-AI-DEPOISON-TARGET` 均按角色槽升序返回首个合格队友，并在能力不足时跳过目标，不消费该目标的随机值。

同两段恢复分支中的物品扫描直接遍历原始来源：NPC 遍历 4 个携带槽，背包遍历 200 个保存槽；先过滤 `itemType == 3`，生命、内力和体力只接受正增量，解毒只接受负的中毒增量，并立即返回首个合格物品。原版不按差值排序，`value` 仅作为 C++ 适配层参数保留，不参与选择，也不触发额外随机调用。

背包槽序由 `sub_2E571` 和 `sub_2B227` 确认：新增物品写入首个空槽，物品耗尽后把后续槽逐项左移，因此顺序是保存槽与插入顺序，不是物品 ID 顺序。`world::state::Bag::orderedItems()` 保留该顺序，并在保存时按相同顺序写回。NPC 物品耗尽后由 `sub_36133` 逐个移动 16 位物品与数量槽；C++ 使用 `world::state::compactCarryItemSlots`，避免旧 `memmove` 长度表达式造成越界读写。

医疗目标依次检查行动代码 8、生命低于 20、受伤高于 40，以及生命低于上限 `1/2`、`1/3`、`1/4`、`1/5` 的条件；前三个比例门槛分别使用 `< 7`、`< 8`、`< 9`。解毒目标依次检查行动代码 9，以及中毒高于 10、20、30、40 的条件；前三个中毒门槛分别使用 `< 4`、`< 6`、`< 8`。`BATTLE-AI-MEDIC-ACTION` 与 `BATTLE-AI-DEPOISON-ACTION` 的施术距离分别为 `medic / 15 + 1` 和 `depoison / 15 + 1`，距离不足时先沿可达路径移动；仍无法施术时，以 `2 * attack <= floor(2 * allyPowerTotal / allyCount)` 选择休息或武功分支。`BATTLE-AI-FOLLOWUP` 的暗器、随机武功和最低内力判断已接入 `Warfield::autoAction`；行动代码 8/9 的请求者完成接近后按原版直接进入随机武功选择。

行动代码 8/9 的请求者分别经过 `sub_361AC` 与 `sub_36209`：存在剩余步数时先接近提供者，随后直接进入 `sub_34C47` 的普通武功选择，并保留 8/9。C++ 通过 `resumeAutoAttack_` 和 `battle::actionCodeForSkill` 复刻该生命周期；只有实际安排移动时才设置续行动标志，无需移动时立即清零，避免标志传给下一名角色。

`BATTLE-AI-MEDIC-ACTION` 与 `BATTLE-AI-DEPOISON-ACTION` 对应行动代码 5/4 的直接支援者。目标不可达时，原版进入休息或普通武功回退，但不会重写当前行动代码；C++ 在 `supportWithoutPosition` 路径保留 5/4。

工具动作的共享收尾位于 `Z.DAT:0x399FE`–`0x39A33`：用毒和解毒函数以 0 体力参数调用，医疗函数先在自身逻辑中扣 2 点体力；三者随后统一增加 1 点战斗经验并再扣 2 点体力。暗器动作在 `0x3A83B` 分支结束，不增加该经验，也不执行共享收尾。

目标选择使用 `sub_36E7F` 对应的地形距离图：只读取地图阻挡，不把角色占位当作障碍。C++ 适配通过 `battle::terrainPathDistance` 复刻目标评分；实际移动和施术仍通过 `battle::shortestPathDistance`/可达格阻止穿越其他角色，并允许进入目标敌人的占位格。离场坐标不会进入 AI active 集合。

`sub_3505B` 的汇编在调用高、低性格或能力目标辅助函数后无条件设置分支标志；当辅助函数没有写入新目标槽时，原版可能继续使用旧的 `word_DC742`。C++ 将空的 `std::optional` 视为分支失败，继续检查后续策略，避免复用旧目标。最近目标函数 `sub_35372` 将初始距离设为 `1000`，并使用严格 `<` 比较；`chooseNearestAiTarget` 保留该边界，距离 `>= 1000` 的候选不会被选中。

`BATTLE-SKILL-DAMAGE` 确认主要伤害波动使用 `random(20)`，负攻防差修正使用 `random(4)`；体力、受伤和距离在随机波动后修正最终伤害。武功附毒使用 1 基战斗等级。`BATTLE-ROUND-END` 对应的角色字段为 `word_90172 = hurt`、`word_90174 = poisoned`，因此回合伤害是 `hurt / 20 + poisoned / 10`。`BATTLE-RANDOM-MOD` 表明原版随机调用是上界独占的模数结果；上界小于等于 `1` 或大于 `30000` 时返回 `0`，且不推进随机数。

`0x395EC` 的吸内力分支已由 IDA 记录随机调用顺序：施放者先执行两次 `random(3)`，随后增加固定内力并执行 `random(addMp / 2)` 增长最大内力，再钳制写回施放者波动；目标最后执行两次 `random(3)`。战斗技能等级上限为 900，存档熟练度字段上限为 999，二者不能混用。

`Z.DAT:0x38555` 的双击循环在第一击完成后无条件进入第二击。第一击已经耗尽内力时，重新计算得到的不可用等级会被钳到 0，而不是取消第二击；每次攻击仍分别执行 `0x38380` 的熟练度增长和命中经验结算。

范围选择的内部父指针也保留原版方向顺序：范围扩展使用「左、上、右、下」，移动扩展使用「上、右、左、下」。当前运行路径不读取 `rangeParent`，因此该差异只作为内部兼容约束记录。

基线 JSON 不写入逐行伪代码。IDA 的类型恢复会随数据库分析状态变化，伪代码应通过 `tools/reverse/ida_backend.py` 按地址即时读取；清单只保存函数地址、范围、名称和人工摘要，以保证哈希稳定。

## 证据状态

- 「已确认」：反编译、汇编指令、字符串引用和调用关系相互支持。
- 「推定」：主要控制流已确定，但数据含义或边界仍有多种解释。
- 「待运行验证」：静态证据不足以排除不同运行结果。
- 「修正版差异」：确认原版存在缺陷，新实现有意采用不同结果。

地址只对本页列出的 SHA-256 文件有效。清单校验失败时，不得套用旧地址。
