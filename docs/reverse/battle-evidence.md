## 二进制结构

`Z.COM` 是 DOS 启动壳，在 `0x10195` 附近通过 `int 21h / AX=4B00h` 执行 `Z.DAT`。该调用点所在函数为 `0x1015F`–`0x101A7`，名称为 `sub_1015F`。`z.DAT` 字符串位于 `0x1010C`；由于执行参数通过寄存器与内存块传递，IDA 没有为该字符串生成普通数据交叉引用，不能据此否定执行关系。

`Z.DAT` 不是 16 位实模式程序。文件头部的 MZ 映像只有 0x2C1C 字节，是 DOS 扩展器加载壳；真正的程序体是紧随其后的 **LE（Linear Executable）32 位映像**，由 Watcom C 编译：

| 项目 | 值 |
| --- | --- |
| LE 头文件偏移 | `0x2C80` |
| 页大小 | `0x1000` |
| 对象 1 | 基址 `0x10000`，1 页 |
| 对象 2（代码与数据） | 基址 `0x20000`，59 页，加载范围 `0x20000`–`0x5B000` |
| 数据页文件偏移 | `0x18A00` |
| 入口 | `0x3F234` |

因此加载后的虚拟地址与文件偏移的关系为 `VA = 文件偏移 + 0x6600`。文件中存放的绝对操作数是对象相对值，加载器通过 LE 内部重定位记录加上对象基址 `0x20000`；`tools/reverse/le_backend.py` 会复现这一过程，得到与 IDA 相同的地址。

反向校验：`src/data/factors.cc` 从文件偏移 `0x4F538` 读取武功兵器绑定表，对应虚拟地址 `0x55B38`，与 `NUM-ATTACK` 中读取该表的指令一致。

字符串 `war.sta` 位于 `0x58A3C`，`fight000.grp` 位于 `0x55B62`。

## 数值规则摘要

以下规则已逐指令确认，并在 `src/battle/formulas.hh` 中标注了对应地址。

### 攻防与伤害（`NUM-DAMAGE`）

1. 知识汇总（`0x3919E`）：遍历全部参与者，条件为 `knowledge > 80`、`hp > 0`、退场标记为 0；与攻击方同阵营者累加到攻击项，否则累加到防御项，累加值均为 `knowledge * 2`。
2. 等级降级（`0x39217`）：从 `skillLevel / 100` 递减，取满足 `mp >= reqMp * ((level + 1) / 2)` 的最大等级，内部以 1 起的形式保存到 `0xE6EC2`。
3. 实际攻击（`0x39294`）：`(attack * 3 + damage[level]) / 2 + 武器攻击 + 防具攻击 + 兵器绑定加成 + 己方知识项`。
4. 实际防御（`0x39331`）：`defence + 防具防御 + 武器防御 + 对方知识项`。
5. 伤害（`0x39391`）：`(攻 − 防 * 3) * 2 / 3 + rnd(20) − rnd(20)`；若结果 ≤ 0 改为 `攻 / 10 + rnd(4) − rnd(4)`；若仍 < 0 记为 0 并跳过后续加成。
6. 加成（`0x39402`）：`+ 攻击方体力 / 15 + 目标受伤 / 20`。
7. 距离衰减（`0x3944C`）：距离 > 10 时 `伤害 * 2 / 3`，否则 `伤害 * (100 − (距离 − 1) * 3) / 100`。衰减无条件执行。
8. 下限（`0x39485`）：最终伤害不小于 1。
9. 经验（`0x39493`、`0x394DF`）：`伤害 / 5`；目标生命扣减后严格小于 0 时再加 `目标等级 * 10`。
10. 受伤（`0x394EE`）：`目标受伤 += 伤害 / 10`，上限 99。
11. 中毒（`0x39529`）：`毒力 = (skillLevel / 100 + 1) * addPoison + poisonAmp`；当 `毒力 > antipoison` 且 `antipoison < 90` 时 `目标中毒 += (毒力 − antipoison) / 15`。该步使用未经内力降级的原始等级，且目标已死亡时同样执行。

### 内力与熟练度（`ATK-EXEC`）

- 双击次数（`0x378F1`）：`doubleAttack == 1` 时为 2，否则为 1。
- 熟练度（`0x38380`）：每次攻击 `skillLevel += rnd(2) + 1`，上限 999，升级时不清零余量。
- 内力（`0x384ED`）：每次攻击扣除 `reqMp * (等级 / 2)`（等级为 1 起），即每个动作一次，而不是每个目标一次。
- 体力（`0x38579`）：全部攻击次数结束后扣 3。

### 辅助行动

| 行动 | 公式 | 体力 | 经验 |
| --- | --- | ---: | ---: |
| 用毒 | `(poison − antipoison) / 4`，钳制 0..99 | 2 | 1 |
| 解毒 | `depoison / 3 + rnd(10) − rnd(10)`，钳制 0..99；`目标中毒 > depoison + 20` 时归零；不超过目标当前中毒值 | 2 | 1 |
| 医疗 | 受伤 ≤ 25 取 `medic * 4 / 5`，≤ 50 取 `3 / 4`，≤ 75 取 `2 / 3`，否则 `medic / 2`，再 `+ rnd(5)`；`目标受伤 > medic + 20` 时治疗量与受伤削减同时归零，但随机数已消耗 | 4 | 1 |
| 暗器 | 受伤 0 取 `addHp / 4`，≤ 33 取 `/ 3`，≤ 66 取 `/ 2`，否则原值，再 `− rnd(5)`，最后 `(值 − throwing * 2) / 3`；`目标受伤 −= 结果 / 4` | 0 | 0 |
| 休息 | `体力 += rnd(3) + (已移动 ? 2 : 3)`；新体力 ≥ 30 时 `生命 += rnd(体力 / 10 − 2) + 3`，内力同式 | — | 0 |

暗器附加毒性（`0x3A73B`）：`addPoisoned > 0` 时 `目标中毒 += max(0, (addPoisoned − 施放者 throwing) / 2 − antipoison) / 2`，`antipoison >= 100` 时为 0；`addPoisoned <= 0` 时 `目标中毒 += addPoisoned / 2 + rnd(5) − rnd(5)`。

### 吸内力（`NUM-DRAIN-MP`）

使用原始 `skillLevel / 100`：`施放者内力 += addMp[等级]`，`施放者内力上限 += rnd(addMp[等级] / 2)`（上限 999），`施放者内力 += rnd(3) − rnd(3)` 后钳到上限；`目标内力 −= drainMp[等级] + rnd(3) − rnd(3)`，下限 0。返回目标实际损失量。

### 菜单开放条件（`MENU-PLAYER`）

全部体力比较使用 `jle`，因此阈值不含等号：移动需 `体力 > 5` 且剩余步数 > 0；武功需 `体力 > 10` 且 `内力 >= 已学武功中最小的 reqMp`；用毒需 `体力 > 10` 且 `poison >= 20`；解毒需 `体力 > 50` 且 `depoison >= 20`；医疗需 `体力 > 50` 且 `medic >= 20`。物品、等待、状态、休息、自动始终开放。

### 战后结算（`WAR-RESULT`、`WAR-SETTLE`、`NUM-LEVELUP`）

胜负判定（`0x3B238`）在每次行动后运行：先把生命 ≤ 0 且未退场的角色移出格子并置退场标记，再检查双方是否还有在场者。己方全灭记 1（失败），敌方全灭记 2（胜利）；同时全灭时结果为胜利。

结算（`0x3B387`）顺序为：

1. 敌方角色生命、内力回满，体力置 100，受伤与中毒清零。
2. 胜利时把战场经验 `warExp / 存活人数` 加到每个存活的己方角色。
3. 己方存活者生命不低于 `生命上限 / 5`；己方倒下者生命置 `生命上限 / 5`，体力不低于 10。
4. 对每个角色：`经验 += 本场经验`，`练功经验 += 本场经验 * 8 / 10`，`制药经验 += 本场经验 * 8 / 10`，三者上限 60000。这一步不看胜负。
5. 胜利（或失败经验开关打开）时才显示经验提示，并依次执行升级（`0x3B6BE`）、练功（`0x3BA85`）与制药（`0x3C2AC`）。

升级（`0x3B6BE`）一次结算全部等级差 `n`，成长系数 `factor = rnd(档位) + 1`，档位按资质取 2、3、4、5、6（分界为 30、50、70、90）：

- `生命上限 += n * 3 * (hpAddOnLevelUp + rnd(3))`，上限 999，随后生命回满、受伤与中毒清零、体力置 100
- `内力上限 += n * 4 * (9 - factor)`，上限 999，随后内力回满
- `攻击、轻功、防御 += n * factor`
- 医疗、用毒、解毒、拳掌、御剑、耍刀在**大于 20** 时各 `+= rnd(3)`；暗器无条件 `+= rnd(3)`；`special` 不成长
- 上述熟练度上限 100

### 练功与制药（`WAR-TRAIN`、`WAR-CRAFT`）

两者共用资质档位 `tier = 7 - potential / 15`，不做钳制。

练功（`0x3BA85`）需求量：`item.skillId != -1` 时为 `(当前等级 + 1) * item.reqExp * tier`，当前等级达到 9 时整步跳过；`item.skillId == -1`（纯属性书）时为 `item.reqExp * tier * 2`。达标后每场战斗只推进一次：套用书本属性，`expForItem` 清零（不是减去需求量），已学得该武功且存储值 < 899 时 `skillLevel += 100`，未学得则放进第一个空槽位。全程不消耗随机数。

书本属性套用（`0x3BC6C`）按固定顺序处理 19 项，与消耗品的属性套用不是同一套规则：`addMaxHp` 与 `addMaxMp` 相加后只判上限 999；`changeMpType` 仅在等于 2 时把 `mpType` 置 2；`addAttack` 到 `addIntegrity` 的十四项相加后钳进 0..100，先判上限再判下限；`addDoubleAttack` 仅在角色当前为 0 时直接赋值；`addPoisonAmp` 相加后钳进 0..100。`addHp`、`addMp`、`addPoisoned`、`addStamina` 四个消耗品字段完全不参与。

制药（`0x3C2AC`）需求量为 `item.reqExpForMakeItem * tier`，`reqExpForMakeItem <= 0` 时不制药。候选配方要求行囊中持有 `reqMaterial`、`makeItem[k] >= 0` 且该数量不少于 `makeItemCount[k]`——`makeItemCount` 是**消耗的材料数量**。反复 `rnd(5)` 直到落在候选上；产出数量在行囊已有该物品时为 `rnd(3) + 1`，新开格子时固定为 1。随后扣除 `makeItemCount[pick]` 份材料并清零 `expForMakeItem`。

### AI 决策级联（`AI-ACTION`）

先统计双方的 `攻击 + 生命` 总和与人数，然后按顺序判定，任一阶段产生行动后不再继续：

1. `体力 < 10` → 休息。
2. `生命 < 20`、`受伤 > 50`、`生命 < 上限 / 2 且 rnd(10) < 3`、`生命 < 上限 / 3 且 rnd(10) < 5`、`生命 < 上限 / 4 且 rnd(10) < 7`、`生命 < 上限 / 5 且 rnd(10) < 9` 任一成立 → 尝试补血物品（`0x33C4D`）。
3. `rnd(10) < 中毒 / 10` → 尝试解毒物品（`0x33E93`）。
4. `内力 < 上限 / 2 且 rnd(10) < 2`、`/ 3 且 < 4`、`/ 4 且 < 6`、`/ 5 且 < 8` 任一成立 → 尝试补内力物品（`0x340D9`）。
5. `体力 > 50` 且（`medic >= 20 且 rnd(10) < 4`、`>= 40 且 < 6`、`>= 60 且 < 8`、`>= 80`）→ 为友方医疗（`0x341F6`）。
6. `体力 > 50` 且 `depoison` 满足同型阈值 → 为友方解毒（`0x343DA`）。
7. `rnd(10) < 5` 且（`生命 < 20`、`生命 < 上限 / 4 且 rnd(10) < 6`、`生命 < 上限 / 5 且 rnd(10) < 8`）→ 逃跑（行动 11，`0x34AEC`）。
8. 其余情况进入攻击决策（`0x34550`）。

补血级（`0x33C4D`）依次尝试：自身 `medic >= 20 且体力 >= 50 且 medic > 受伤 - 30` 时自疗；否则在物品中找 `addHp > 0`；否则找 `depoison`/`medic` 满足条件的友方并登记求助标记，本回合仍照常攻击。解毒级（`0x33E93`）结构相同，判据换成 `depoison` 与中毒值。己方使用共享行囊（200 格），敌方使用角色自带的 4 格物品。

为友方医疗（`0x341F6`）按参与者顺序取第一个满足条件者：对方已登记求医标记，或 `生命 < 20`、`受伤 > 40`、`生命 < 上限 / 2 且 rnd(10) < 7`、`/ 3 且 < 8`、`/ 4 且 < 9`、`/ 5`；前置条件为 `我方 medic > 对方受伤 - 30`。为友方解毒（`0x343DA`）的判据为中毒 `> 10 且 rnd(10) < 4`、`> 20 且 < 6`、`> 30 且 < 8`、`> 40`。

### AI 攻击决策（`AI-ATTACK`）

1. 若「敌方战力均值 / 2 > 自身生命 + 攻击」且「己方战力总和 > 敌方战力总和 * 2」，则改为辅助：`medic >= 20 且体力 >= 50` 时医疗生命缺口最大的友方，否则 `depoison >= 20 且体力 >= 50` 时为中毒值最高的友方解毒。
2. `用毒熟练 - 攻击 > rnd(50)` 且 `rnd(150) < 用毒熟练` 时使用用毒。
3. 扫描物品投掷：己方要求 `|addHp| > 攻击 * 3 / 2` 且 `rnd(暗器熟练) > 20`，敌方只要求 `|addHp| > 攻击` 且 `rnd(10) < 6`；毒性物品要求 `addPoisoned > 同一门槛` 且 `rnd(10) < 3`。
4. `体力 > 10` 且 `内力 >= 已学武功中最小的 reqMp` 时普通攻击，否则休息。

普通攻击（`0x34C47`）在已学武功中**随机**选一门，用 `AI-TARGET` 取目标，按 `attackAreaType` 判定射程（0 与 3 只看距离，1 与 2 还要求同排或同列）。射程内直接出手；否则移动（`0x3650E` 从射程上限向下找站位，取离当前位置最近的一格），移动后再判，仍不行则改取最近的敌人重判，最后休息。

目标选择（`AI-TARGET`）：`integrity >= 75` 且 `rnd(10) < 7` 取攻击最高的敌人；`integrity <= 25` 且 `rnd(10) < 7` 取攻击最低的；`potential >= 70` 且 `rnd(10) < 7` 取敌方辅助（己方有用毒者时取解毒最高者，否则取医疗最高者，均要求该熟练 ≥ 20）；其余取路径距离最近的敌人。用毒目标（`AI-TARGET-POISON`）只考虑 `中毒 < 95` 且 `抗毒 < 我方用毒` 的敌人，`potential > 60` 且 `rnd(10) < 7` 时取攻击最高者，否则取最近者。

撤退落点（`AI-RETREAT`）只在「恰好用尽全部移动力」的格子中挑选，取到敌方各角色曼哈顿距离之和最大的一格；逃跑随后休息，用物品前的撤退不休息。

## 证据状态

- 「已确认」：反编译、汇编指令、字符串引用和调用关系相互支持。
- 「推定」：主要控制流已确定，但数据含义或边界仍有多种解释。
- 「待运行验证」：静态证据不足以排除不同运行结果。
- 「修正版差异」：确认原版存在缺陷，新实现有意采用不同结果。

地址只对本页列出的 SHA-256 文件有效。清单校验失败时，不得套用旧地址。

## 复现方式

不安装 IDA 时使用 LE 后端：

```powershell
$env:PYTHONPATH=(Resolve-Path 'tools/reverse').Path
$env:HOJY_ORIGINAL_DATA_DIR='D:\DOS\LEGEND'
python -m pip install capstone
python -m unittest tests/reverse/test_le_backend.py -v
```

`tools/reverse/le_backend.py` 提供 `LEImage`（重定位后的平坦映像）与 `FunctionIndex`（函数边界、调用关系、立即数检索、反汇编清单）。函数边界以 Watcom 栈检查序列 `push <帧长>; call 0x3ED1E` 为主依据，共识别 284 个入口，再并入落在指令边界上的 `call rel32` 目标，合计 589 个，与 IDA 报告的 570 个同量级。
