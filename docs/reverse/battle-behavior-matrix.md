# 战斗行为逆向矩阵

本矩阵是战斗核心、AI 和回归测试的工作清单。每项行为必须关联逆向证据或明确的下一步分析动作。

| 行为 | 当前状态 | 证据/下一步 |
| --- | --- | --- |
| 回合行动顺序 | 已确认 | `sub_3271E` 先对全部原始槽即时交换排序，再反向消费；死亡高速槽仍会影响同速存活槽顺序。C++ 先排序后过滤死亡槽，保留该副作用 |
| 回合结束中毒与受伤结算 | 修正版差异 | `sub_3C563`：生命减少 `hurt / 20` 与 `poisoned / 10`；原版仅在结果小于 0 时改为 1，结果恰为 0 会保留 0，新实现统一最低保留 1 点 |
| 移动步数与阻挡 | 已确认 | 步数为 `max(0, speed / 15 - hurt / 40)`；四方向优先级为「上、右、左、下」，对应 `word_556DE` 与 `word_556E6` |
| 范围扩展方向 | 已确认 | 范围 BFS 的方向优先级为「左、上、右、下」；移动 BFS 仍为「上、右、左、下」。该顺序只影响等距 `rangeParent`，不改变可达集合 |
| 角色占位与死亡清理 | 已接入，待运行验证 | `Warfield::endTurn` 清理死亡角色占位并按地图边界写回坐标 |
| 单体技能范围 | 已接入 | `BATTLE-SKILL-SELECT` 读取熟练等级 `selRange`，通过可达格与目标格交集校验 |
| 直线技能范围 | 已接入 | `BATTLE-AI-MOVE-TO-RANGE` 使用正交目标和方向优先级；`startActAction` 按距离逐格结算 |
| 十字技能范围 | 已接入 | `BATTLE-SKILL-SELECT` 仅接受同轴目标，`startActAction` 按四方向逐格结算 |
| 区域技能范围 | 已接入 | `BATTLE-SKILL-SELECT` 使用目标周围 `area` 半径，结算时裁剪地图边界并计算距离衰减 |
| 实际攻击计算 | 已确认 | `BATTLE-SKILL-DAMAGE`：基础值为 `(3 * attack + skillDamage) / 2`，再叠加装备与阵营知识修正 |
| 实际防御计算 | 已确认 | `BATTLE-SKILL-DAMAGE`：防御与阵营知识修正合并后按 3 倍参与攻防差 |
| 内力不足时武功等级降级 | 已确认 | 从当前等级向 0 级递减，选择首个满足 `reqMp * ((level + 1) / 2) <= mp` 的等级；0 级不消耗内力 |
| 伤害随机波动 | 已确认 | `BATTLE-SKILL-DAMAGE`：主要波动为两次 `random(20)` 之差；攻防差为负时改用两次 `random(4)` |
| 体力与受伤修正 | 已确认 | `BATTLE-SKILL-DAMAGE`：伤害增加 `attacker.stamina / 15` 与 `defender.hurt / 20`，命中后受伤增加 `damage / 10` |
| 距离衰减 | 已确认 | 距离 2–10 使用 `100 - 3 * (distance - 1)` 百分比；距离大于 10 时保留 `2/3` |
| 吸取内力 | 已确认 | `0x395EC` 的随机调用顺序为施放者先两次 `random(3)`，写入固定 `addMp`，再 `random(addMp / 2)` 增长最大内力，钳制并写回施放者波动，最后对目标执行两次 `random(3)` |
| 攻击附加中毒 | 已确认 | 抗毒低于 90 时比较攻击方毒性、1 基武功等级附毒与目标抗毒，正差按 `/ 15` 增加中毒 |
| 用毒 | 已确认 | `BATTLE-ACT-POISON`：实际增加量为 `max(0, (poison - antipoison) / 4)`，受中毒上限限制 |
| 医疗 | 已确认 | `BATTLE-ACT-MEDIC`：施术者体力至少 50；按受伤分段计算恢复量并加入 `random(5)`，随后降低受伤值 |
| 解毒 | 已确认 | `BATTLE-ACT-DEPOISON`：减少量为 `depoison / 3 + random(10) - random(10)`；目标中毒高于 `depoison + 20` 时不生效 |
| 工具动作共享收尾 | 已确认 | `Z.DAT:0x399FE`–`0x39A33`：用毒、解毒和医疗完成后固定增加 1 点战斗经验并扣除 2 点体力；医疗函数本身另扣 2 点体力；暗器不经过该收尾 |
| 暗器 | 已确认 | `BATTLE-ACT-THROW`：生命、受伤和中毒写入顺序已确认，正中毒分支使用投掷能力和目标抗毒 |
| 休息 | 已确认 | `BATTLE-ACT-REST`：体力增加 `random(3) + 2` 或 `+3`；体力达到 30 后生命、内力分别增加 `random(stamina / 10 - 2) + 3` |
| AI 资源物品选择 | 已确认 | `BATTLE-AI-HP-RECOVERY`、`BATTLE-AI-DEPOISON-RECOVERY`：只扫描 `itemType == 3` 的 NPC 携带槽或背包保存槽，按原始槽序返回首个属性方向合格的物品；生命、内力和体力要求增量为正，解毒要求中毒增量为负，不按差值排序，也不额外消费随机值 |
| 资源物品槽维护 | 已确认 | `sub_2E571` 与 `sub_2B227` 保持背包插入槽序；`sub_36133` 在 NPC 物品耗尽后逐个压缩 4 个物品与数量槽。`mem::Bag::orderedItems()` 与 `mem::compactCarryItemSlots` 已接入，并覆盖保存尾槽清理和槽 0/1/2 压缩回归测试 |
| 双击 | 已确认 | `Z.DAT:0x38555`：第一击扣除内力后仍无条件执行第二击；若剩余内力不足，第二击降到 0 级，不取消行动；两次命中分别结算伤害经验和熟练度 |
| 武功熟练度成长 | 已确认 | `Z.DAT:0x38380`：每次攻击后增加 `random(2) + 1`，存储值上限为 999；跨越百位等级时保留余量，不向下取整 |
| AI 体力优先级 | 已确认 | 体力低于 10 时先记录休息；若生命恢复分支被触发但没有可执行动作，原版会清除该休息选择并继续判断 |
| AI 生命优先级 | 已确认 | 生命低于 20 或受伤高于 50 时立即尝试恢复；`1/2`、`1/3`、`1/4`、`1/5` 阈值依次使用 `< 3`、`< 5`、`< 7`、`< 9` 门槛；自身与物品均不可用时，首个合格医疗提供者使当前槽保存行动代码 8 |
| AI 解毒优先级 | 已确认 | 自身解毒门槛为 `random(10) < poisoned / 10`；命中后依次尝试自身能力、物品和队友能力，合格提供者使当前槽保存行动代码 9 |
| AI 内力补充优先级 | 已确认 | `1/2`、`1/3`、`1/4`、`1/5` 阈值依次使用 `< 2`、`< 4`、`< 6`、`< 8` 门槛 |
| AI 医疗支援门槛 | 已确认 | 体力高于 50 后，医疗能力达到 20、40、60 时依次使用 `< 4`、`< 6`、`< 8` 门槛；达到 80 时最终无条件尝试 |
| AI 解毒支援门槛 | 已确认 | 与医疗支援使用相同的能力阈值和随机消费顺序 |
| AI 队友支援执行 | 已确认 | `BATTLE-AI-MEDIC-TARGET` 与 `BATTLE-AI-DEPOISON-TARGET` 按角色槽顺序选取首个合格目标；场景副本的行动代码 `8/9`（纯 AI 门面的 `AiRequest` 映射值）在同一回合保留到后续队友决策；请求者先向提供者靠近，再进入普通攻击选择，并在无移动路径时清除续行动标志；施术距离为 `ability / 15 + 1`，无法进入范围时按 `2 * attack <= floor(2 * allyPowerTotal / allyCount)` 选择休息或武功分支，其中 `attack` 使用基础攻击值 |
| AI 施术范围与移动 | 已确认 | 目标/范围图只读取地形阻挡，实际移动格感知角色占位；无法在本回合进入范围时先移动到可达 frontier，移动后只复查一次；用毒使用 `Reposition` 保持最大允许站距，备用目标不再安排第二次移动 |
| AI 入场属性快照 | 已确认 | `sub_33599`、`sub_34550`、`sub_3505B`、`sub_3540E`、`sub_35667`、`sub_36210`、`sub_363AC` 直接读取战斗运行时字段；C++ 在装备合并前保存快照，运行时修改通过入场装备增量还原，避免把装备加成重复计入 AI |
| AI 规划等级与执行等级 | 已确认 | 规划范围使用存储熟练度等级；施术执行使用当前 MP 可负担等级。两者分离，不能用 MP 降级结果反推站位范围 |
| pending action 生命周期 | 已接入 | `Warfield` 通过 `battle::runPendingAction` 先移动取出回调再调用；回调内部新建的 pending action 不会被外层清除 |
| AI 技能可用性 | 已确认 | `BATTLE-AI-RANDOM-SKILL` 统计正武功 ID 并按随机序号映射回真实槽位；场景适配同时支持稀疏槽位 |
| AI 移动目标 | 已确认 | 目标评分使用只读取地形阻挡的 `sub_36E7F` 距离图；实际移动和施术路径仍使用带角色占位阻挡的可达格，目标占位格可进入 |
| AI 行动 11 撤退 | 已确认 | `BATTLE-AI-SELECT` 在最后后续行动前消费 `random(10) < 5`，命中后按生命门槛触发 `BATTLE-AI-RETREAT`，移动后休息 |
| AI 随机武功 | 已确认 | `BATTLE-AI-RANDOM-SKILL` 统计正武功 ID 数量后执行 `random(count)`，再映射回原始槽位；不按伤害评分加权，稀疏槽位同样兼容 |
| AI 目标策略 | 已确认 | `BATTLE-AI-TARGET-STRATEGY`：integrity 高低、potential 和能力字段决定攻击最高、最低、能力目标或最近目标；严格比较保留首槽 |
| AI 目标空候选 | 修正版差异 | 原版 `sub_3505B` 的触发分支可能保留旧目标槽；C++ 将空结果视为分支失败，继续后续策略并使用 `sub_35372` 的严格 `< 1000` 最近距离上限，避免复用过期目标 |
| AI 候选生成与评分 | 已确认 | 原版不存在前三候选伤害加权；当前实现不再使用旧评分模型，改用随机武功槽、目标策略和范围校验 |
| AI 平分决胜 | 已确认 | 原版目标与撤退扫描均使用严格 `<`/`>`，不消费随机值；随机只用于行动分支门槛和武功槽选择 |
| 胜负判断 | 已接入 | 战场结束由存活阵营检查统一处理，死亡槽和离场槽不再参与存活计数 |
| 失败时经验开关 | 已确认 | 个人战斗经验始终先累计；战场经验仅胜利均分；失败时 `getExpOnLose` 只控制升级、练功和制药后续步骤 |
| 战后升级与练功 | 已接入 | 多级升级先计算层数后一次成长；熟练度存储上限 999，战斗技能等级上限 900；练功每场只推进一次 |
| 战后制药与物品制作 | 已接入 | 扫描全部 5 个配方槽，材料不足不选；新产物固定 1 个，已有产物为 `random(3)+1`，先加产物再扣材料 |

## 已解决的历史候选

- `battle::predictDamage` 仅保留兼容门面和测试能力，生产 AI 与界面流程不调用，因此不存在预测防御遗漏知识修正的问题。
- 攻击附加中毒统一返回目标实际增加的正值；界面与状态写入使用相同符号。
- 用毒目标读取旧候选距离的问题已确认为原版缺陷；当前实现按当前候选计算距离，并在上表标记为「修正版差异」。
